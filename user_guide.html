User guide

Using the Pathology Structured Extractor

A walkthrough of the app itself — upload reports, pull structured fields out of them with an LLM, check the results against ground truth, and export what you need. Five tabs, one pipeline.

Yonghua Zhuang

00Overview

You give it an Excel file of pathology reports. It sends each report to an LLM along with a list of fields you want pulled out — stage, grade, margin status, receptor results, whatever the case calls for — and hands back a table with one row per case and one column per field.

If you also have a ground-truth spreadsheet for the same cases, the app scores every field automatically the moment extraction finishes, so you can see accuracy without a separate comparison step.

01Getting started

  1. 1

    Open the app's URL in your browser. Browsing and setting up fields is free without an account — but running an extraction requires signing in, since results and API usage are tracked per user.

  2. 2

    Open the sidebar and use Create account the first time — pick a username (lowercase letters, digits, underscores) and a password of at least 6 characters. After that, Sign in with the same credentials.

  3. 3

    Upload a report file under Reports file in the sidebar. It needs one column with a case ID and one with the report text — for the bundled practice datasets, those are ID and Report.

  4. 4

    Optionally, upload a Ground truth file with the correct answers for the same cases. This unlocks automatic accuracy scoring everywhere in the app.

Shared key vs. your own

If this deployment has a shared key configured, it only ever shows up as an option for OpenAI, and it's capped at 1,000 calls — the progress bar above ("X / 1000 calls used") tracks how much of that you've used. Every other provider — and OpenAI too, once you've used up the shared budget or would rather not draw against it — needs My own key: paste a key from that provider's site and click Add. A green confirmation line appears once it's set.

Once that 1,000-call cap is hit, extraction stops making new calls against the shared key specifically; switch to My own key to keep going.

Keys are session-only by default — closing the tab or signing out clears them, and you'll paste again next time. If you're signed in, a 💾 Remember this on this device (encrypted) checkbox appears once a key is set; check it to save an encrypted copy to your account so you don't have to re-paste on your next sign-in. It's encrypted with a key derived from your account password, so only you can decrypt it — resetting that password makes any saved copy unrecoverable.

Azure OpenAI works differently

Azure OpenAI the service supports a static API key too, but this app's Azure integration authenticates with a short-lived Entra ID bearer token from your institution's Azure CLI login instead, and has its own Deployment name and Resource endpoint fields instead of a model dropdown. It gets a full walkthrough of its own in Using Azure OpenAI.

Before you upload — PHI

Whatever provider is selected above receives the report text you upload. For the three public providers (OpenAI, Google Gemini, OpenRouter), that means report text leaves your institution's network and reaches a public third-party API — do not upload reports with PHI — upload only de-identified or synthetic reports. Azure OpenAI keeps report text within your institution's own deployment, but you should still confirm with your IT/privacy office that this specific setup is approved for PHI before uploading real patient reports. The app repeats this same caution directly above the file uploaders once a provider is picked.

03Walking through the tabs

The five tabs run left to right along the top of the app, each one stage of the same pipeline: define what to pull out, run it, compare approaches, triage the results, then correct and export.

1 · Fields & Prompt

Decide what the extractor should look for. Apply a built-in preset for a supported cancer type — it fills in the field list, the allowed values for each field, and (where available) the ground-truth column mapping for you. Or skip the preset and add your own fields with the + button, each with its own name and a slash-separated list of allowed values (e.g. present/absent/Not mentioned).

On the right, pick a prompting strategy — see Prompting strategies below — and the exact prompt that will be sent is rendered live underneath it, so you can sanity-check it before spending any API calls.

2 · Run & Results

Press Run Extraction. Every report is sent once (twice for the verification strategies) and the results land in a table, one row per case. If a ground-truth file is attached and mapped, per-field accuracy appears automatically — no extra step.

Every result is cached by report text and prompt. Re-running the same case with the same prompt returns instantly at no cost — useful when you're only tweaking the prompt for one field and don't want to re-pay for the rest.

3 · Compare Strategies

Select two or more prompting strategies and the app runs the same reports through each, then shows a side-by-side accuracy heatmap, field by field. This is the fastest way to answer "is Chain-of-Thought actually worth the extra tokens for this cancer type?" with data instead of a guess.

4 · Review

Step through the results case by case. Where the model got something wrong, edit the value in the Corrected column — the original extraction stays visible alongside it. When you're done, download the final CSV with your corrections merged in.

5 · Cohort

Define inclusion/exclusion criteria against the extracted fields — for example, "T-Stage is pT3 or higher" — and see how many cases would survive that cohort definition, plus a breakdown of why the excluded ones were dropped.

06Using Azure OpenAI

If you're at an institution whose IT department already runs an Azure OpenAI resource, this is the provider to use — reports stay on institutional infrastructure instead of going to a public API. It works a little differently from the other three providers, so it gets its own walkthrough.

The key difference

OpenAI, Gemini, and OpenRouter all take a long-lived API key you paste in once. Azure OpenAI itself supports a static key too — many institutions disable it for security/compliance reasons and require Entra ID (Azure AD) authentication instead, which is the path this app implements: you sign in with your institutional account and generate a short-lived bearer token rather than pasting a permanent secret. If your institution's Azure resource does have a static key enabled, this app doesn't have a field for it — the bearer-token flow below is the only Azure path it supports.

Your institution's setup may differ

The steps below were written against one specific institutional Azure OpenAI deployment. The az login and token commands are standard Azure CLI syntax that work for any Azure AD account, but whether Entra ID auth is required at all, whether a VPN is needed, and how resources and deployments are named are all choices each institution's IT department makes independently. If you're setting this up somewhere other than where this guide was written, treat the steps as a template and confirm the specifics — especially network access and resource/deployment names — with your own IT or Azure administrator before assuming they'll match exactly.

  1. 1

    Prerequisites: the Azure CLI installed (az), signed in to your institutional account, and — if the resource sits on a private network, as is typical — connected to your institution's VPN or on-campus network. Check IT documentation for your institution's exact resource name and required network access.

  2. 2

    Sign in and get a bearer token. If you haven't already:

    terminal
    az login

    Then generate a token scoped to Azure Cognitive Services — this is the exact command the app itself shows you, so you can copy it from either place:

    terminal
    az account get-access-token \
  --resource https://cognitiveservices.azure.com \
  --query accessToken -o tsv

    This command's entire output is the token — one long line starting with eyJ…, no quotes or JSON around it. Copy that whole line; you'll paste it into the app in step 4. It's short-lived, so if requests ever start failing with an authentication error, just re-run this command and paste the fresh token in.

  3. 3

    In the app sidebar, set Provider to Azure OpenAI. The fields below it change to match: a Deployment name box, a bearer-token key field, and a Resource endpoint field — instead of the usual model dropdown and static API key.

  4. 4

    Type the exact Deployment name your institution has configured into the box provided — not a generic model name like gpt-4o, but whatever your IT team named the deployment when they set it up. Ask your Azure administrator, check the Azure Portal, or run:

    terminal
    az cognitiveservices account deployment list \
  --name <your-resource-name> \
  --resource-group <your-resource-group>
  5. 5

    Paste the bearer token from step 2 into the key field and click Add. You should see a green confirmation that the key is set.

  6. 6

    Set Resource endpoint to just your resource's base URL — no path, no deployment name:

    resource endpoint
    https://<your-resource>.openai.azure.com

    You'll find this on the resource's "Keys and Endpoint" page in the Azure Portal. The app builds the full request URL for you from this plus the deployment name from step 4 — it shows the result as a "Full endpoint" caption underneath, so you can sanity-check it before running anything.

  7. 7

    Optional — remember these settings. If you're signed in to the app, a 💾 Remember this on this device (encrypted) checkbox appears below the key field. Checking it encrypts your deployment name, resource endpoint, and current token and saves them to your account, so you don't have to retype the deployment/resource next time you sign in.

    The bearer token itself is still short-lived even when saved — sign-in will restore it, but if it's already expired you'll just paste a fresh one over it and check the box again. Resetting your app account password also invalidates anything saved this way.

  8. 8

    Set up your fields and preset as usual (see Walking through the tabs) and run extraction — requests now go to your institution's Azure endpoint instead of the public API.

Common errors

DeploymentNotFound — the Deployment name doesn't match an actual deployment on the resource. Double-check against the az cognitiveservices account deployment list output from step 4; a placeholder or guessed name (like assuming gpt-4o-mini exists) will fail even if that model exists elsewhere.

Connection timeout, or the run just hangs — usually means you're not on the VPN or network the private endpoint requires. Confirm you're connected, then retry. Also double-check the Resource endpoint has no typos and no trailing path — the app's "Full endpoint" caption should look like a real, complete URL before you hit Run.

Worked before, now failing with an auth error — the bearer token expired. Generate a new one (step 2) and paste it in again — this is normal, not a bug, and happens whether or not you're using "Remember this on this device."

07Tips & troubleshooting

Sidebar flagged something after I uploaded reports?

That's the PHI pre-pass — a local regex scan that runs on every uploaded reports file and looks for common identifier patterns (SSNs, phone numbers, emails, labeled MRN/DOB/name fields, street addresses). It's a heuristic safety net, not certified de-identification — a clean scan means "no obvious red flags," not a guarantee. Upload only de-identified or synthetic reports regardless of what it shows.

Run & Results flagged a consistency issue?

That's the consistency check — a local, deterministic check on the fields you already extracted, not another LLM call. It catches values outside a field's own defined options (e.g. a stray pMX), more positive lymph nodes than nodes examined, and N-Stage N0 paired with a nonzero positive-node count. It never edits anything — it just flags cases worth a closer look in Review.

What does 🧠 Explain this case do?

One LLM call, for the whole case, asks the model what in the report supports each extracted value — and to say plainly when a value is a direct quote versus an inference, unit conversion, or interpretation. A field flagged ⚠️ UNSUPPORTED means the model itself doesn't think the report backs up that value, worth a close look. This is the model's own after-the-fact explanation, not proof — a starting point for review, not a guarantee.

Can I describe my cohort instead of building rules field-by-field?

Yes — in the Cohort tab, open "Describe your cohort in plain English" above the Inclusion/Exclusion table and type something like "liver cases with vascular invasion and R1 margins." One LLM call translates it into rules using your actual extracted fields and their allowed values — shown as a preview first. Nothing is added to the table until you click Add these rules.

No accuracy numbers showing up?

Check the GT column mapping expander in the sidebar — each extracted field needs to be matched to the right column in your ground-truth file. Built-in presets pre-fill this for you; custom field sets need it set by hand.

Re-running feels instant

That's the cache working as intended — identical report text plus identical prompt returns the stored result instead of calling the API again. Change the prompt, strategy, or field list and it'll extract fresh.

Uploaded the wrong preset by accident?

Switching the preset in Fields & Prompt resets the field list and the GT column mapping — reapply the one you meant to use and you're back to a clean state.

Signing in partway through setup?

If you configure fields or upload files while signed out and then sign in (which you'll need to do before running anything — see Getting started), the app resets to your account's saved defaults. Re-apply your preset and re-attach your ground-truth file after signing in, then you're good to run.

Questions the app itself can answer: the Help tab in the top nav has a condensed reference for all of the above, plus the full prompting-strategy table, without leaving the app.
